# 天空积云

主页草地上方的写实积云。**没有改动兔子、气泡、语录、原有灯光和草地代码**，
只在引擎里新增了四个方法并挂进已有的构建 / 更新流程。

## 一句话实现

```
makeCloudTexture()   现场画 4 张积云密度图（canvas + fbm 噪声，无外部贴图）
        ↓
makeCloudMaterial()  一个着色器：密度渐变当受光面 → 明暗层次；四周虚化 → 软边
        ↓
buildClouds()        3 个深度带 × 8 朵云，每朵 4 层半透明贴片
        ↓
updateClouds()       横向缓慢漂移 + 到边循环；顺带喂时间给"自呼吸"
```

## 一、为什么不用圆球堆叠

Q 版云是几个球拼起来的，边缘硬、明暗简单。这里用的是**单张密度图 + 屏幕空间的
伪体积光照**：

1. 密度图：6 个圆团取并集 → 积云轮廓（上头鼓、底下平），再用两层 fbm 噪声做域扭曲，
   边缘就被"气流"拱得不规则；软阈值把轮廓切成厚实/稀薄两级。
2. 立体感：在着色器里取密度的**梯度**当表面法线，拿太阳方向点乘 —— 朝光的一面亮、
   背光面暗。这不是烘焙上去的高光，是逐像素算的，配合下面 "薄处透天光" 会自己长出体积。
3. 软边：贴图四周本来就是透明的，着色器再按 UV 收一道边（`smoothstep`），任何角度都不会
   出现硬边或方块感。

## 二、明暗与场景一致

云的颜色不是写死的，`buildClouds()` 会从场景现有的两盏灯里读色值：

| 用途 | 来源 |
| --- | --- |
| 受光面 `uSun` | 太阳 DirectionalLight 的颜色，往白色提亮 62% |
| 薄处天光 `uAmbient` | HemisphereLight 的天顶色 |
| 背光面 `uShadow` | 天际色压暗 48%，掺 16% 太阳色 |
| 远处雾色 `uHaze` | 场景 `FogExp2` 的雾色 |

光照方向也是从既有的 `this.sunDir`（太阳光和天空太阳盘共用的那个向量）投影到画面上得到的。
所以云的色温和草地、天空是同一套，**但原有灯光的参数一个都没动**。

## 三、摆放与漂移

- **三个深度带**：z = -72 / -112 / -158，越远越大越淡（不透明度 0.92 / 0.74 / 0.54，
  雾掺入 0.08 / 0.18 / 0.30）—— 这就是空气透视。
- **高度按屏幕位置算**：`worldYAtScreen(screenY, z)` 把目标屏幕高度反投影到该深度的平面，
  `horizonScreenY()` 给出地平线位置，云带取地平线的 8%~52%。这样手机上（fov 66、俯角 19°）
  和桌面上（fov 55、俯角 3°）都稳定落在天空里，不会像写死世界坐标那样在手机上飘出画面。
  窗口尺寸变化时 `syncCloudHeights()` 按新相机重算一遍。
- **漂移**：每朵 0.35~1.3 单位/秒，到 ±172 循环。投影到屏幕上大约 4~12 像素/秒，
  看得出在动但不抢注意力。每层的 `uPhase` 不同，云体还会自己轻轻"呼吸"。
- **始终朝向镜头**：每帧按方位角转向相机，飘到画面两侧也不会因为侧看被压扁。

## 四、不挡兔子、不抢点击

- 云在 z = -72 之后，兔子在 z ≈ 12.7：云**全部在兔子后方**，深度测试下会被兔子正确遮挡。
- 云的高度都在兔子头顶之上（`check-bubble.mjs` 会验证"兔子中心那条竖线上，云底不低于兔头"）。
- 每个云片 `mesh.raycast = function () {}`：任何射线拾取都碰不到它们。
  点兔子本来就走屏幕空间椭圆判定，这里是双保险。

## 五、性能

8 朵 × 4 片 = 32 个带透明混合的 quad，每帧只更新 32 个 `uTime` 和 8 个旋转，
密度图在初始化时一次性生成（4 张 256×256，约几十毫秒，在开场蒲公英遮挡期间完成）。
手机上云整体缩小到 0.6 倍，避免一堵白墙压在只有 170px 高的天空里。

## 六、自检

`node scripts/check-bubble.mjs` 里新增了 9 项（累计 58 项）：

- 云层已生成、数量 4~12 朵、每朵 ≥3 层贴片
- 云全部在兔子后方、全部在兔子上方、所有云片禁用了射线拾取
- 云在横向漂移，且速度 <3 单位/秒（平缓）
- 兔子中心那条竖线上，云体不会压到兔头以下
