# 兔子对话气泡

主页那只毛绒兔子头顶的对话气泡：加载后自动说欢迎语，点它会跳一下、"啾"一声、
换一句关心话术；问诊回答也能落到气泡里。**没有语音朗读**，纯文字。

## 一句话架构

```
语录库 src/data/rabbit-quotes.ts
        ↓
说话总线 src/lib/rabbit-speech.ts   ← 谁都能调用（业务模块 / 控制台 / 表单）
        ↓
气泡组件 src/components/RabbitBubble.tsx
        ↓
3D 引擎 rabbitAnchor()  src/components/meadow/engine.js  ← 只做投影，不碰模型
```

## 一、兔子的大小与站位

兔子在 `layoutBall()` 里定位置：桌面上 `x=2.45, z=12.7`（z 越大离镜头越近；x 从 3.35 收回来过，原来太贴右边），
整只缩放到 `homeScale = 1.1`；手机上 `x=0.5, z=11.4`。脚底高度跟着缩放一起抬
（`1.12 × scale`），否则放大后会陷进草里。趴到问诊框沿时会插值回 0.23。
**只改代码里的位置和缩放，GLB 文件、材质、自转、浮动都没动。**

## 二、气泡怎么跟着兔子

引擎新增两个只读方法，**不改兔子的位置、旋转、缩放和毛绒材质**：

| 方法 | 作用 |
| --- | --- |
| `meadow.rabbitAnchor()` | 返回兔子头顶的屏幕坐标 `{x, y, cx, cy, rx, ry, flowing, perched}`（CSS 像素） |
| `meadow.hitRabbit(x, y, pad)` | 判断某个屏幕坐标是否落在兔子身上（椭圆判定，比 raycast 便宜、对耳朵更宽容） |
| `meadow.hop(power)` | 跳一下（0.52 秒，起跳压扁、空中拉长、落地回弹，幅度可传 0~1） |

气泡每帧读 `rabbitAnchor()`，用 `translate3d` 贴上去（不触发 React 重排）。
摆放顺序：

1. **正上方** —— 兔子站在草地上时头顶是一整片天，走这条。
2. **右侧** —— 兔子趴到问诊框右上沿时上方只有几十像素，改挂右边。
   气泡的左沿不会越过「面板右边界 − 20px」，否则回复气泡变高时会盖住面板右上角的
   档案详情 / 关闭按钮（`panelRightRef` 由 `syncPerch` 量出来后传进来）。
   两边离得远时小尖角会自动拉长（`--tail-reach`，最长 46px）伸到兔子脸边。
3. **左侧** —— 右边也放不下时。
4. **让位** —— 手机开着问诊框时四周都挤，这时**不显示**气泡（回答本来就在对话框里，
   硬塞会把兔子整个盖住）。

小尖角的方向跟着摆放位置走，并且始终指向兔子；气泡被视口夹住时会自动调整尖角位置。

转场飞行（兔子从草地滚到框沿）的 1.1 秒里气泡淡出，落定后再出现，不会横穿整屏。

## 三、注视：真的看着鼠标

原来的做法是「鼠标相对兔子的屏幕偏移 × 系数」。手机能用，因为兔子就在屏幕中间、
相机在它正前方；桌面兔子在 x=3.3（相机看它是从 28° 左前方），那套映射等于把
"正脸"定在了偏右的方向上 —— 鼠标停在兔子身上时反而是歪的。

现在改成把指针在**兔子所在深度**反投影成世界坐标，直接算朝向：
鼠标落在兔子身上 → 目标点就是兔子自己 → 正脸看着你；鼠标在左边 → 转头向左。
左右限位不对称（朝镜头一侧 43°、另一侧 25°），因为脸是画在球面上的，
往镜头反方向转太多就只剩侧后方了。

## 四、脸上的补光（柔光）

兔子是奶油白的毛，草地上正面的光比较散，脸容易发平。引擎里加了一盏**跟着兔子走的小点灯**
（`faceLight`，暖白 `#fff2df`）：

- 位置：从兔子往镜头方向 **1.85 × scale**，再往右 0.30、往上 0.42 —— 在"镜头和脸之间、略偏右上"。
- 强度：`1.7 × scale²`。距离随 scale 缩小、强度按平方补回来，站在草地和趴框上亮度一致。
- `distance` 限在 4.2、不投影，基本只影响兔子本体，不会把草地照出一块光斑。

**要的是柔光，不是高光**：灯从 1.45 个身位拉到 1.85，强度降到原来的五成，
偏移也收小 —— 脸上一开始是一块明显的高光，苹果肌和额头会过曝，现在是一层均匀的暖光，
腮红、鼻子、眼睛的深浅都还在。`scripts/tune-face-light.mjs` 可以重拍强度对比。

## 五、点击音效与跳跃

- 音效不加载音频文件，`src/lib/rabbit-sfx.ts` 用 WebAudio 现场合成：
  一个先上滑再回落的带颤音正弦 + 高八度亮片 + 落地一声轻"咚"，约 0.3 秒，很轻。
  `setRabbitSfxMuted(true)` 可以整体关掉（给以后的静音按钮预留）。
- 跳跃在引擎里：`hop()` 起跳，`updateBall` 里叠加位移和伸缩，0.52 秒回到原位。
  趴到框沿之后幅度自动减半，不会飞出视口。

## 六、从科普库 / 药品库回来

以前从疾病、药品页点返回，会把蒲公英开场重放一遍：服务端渲染出来的是 `.boot` 覆盖层，
要等 hydration 跑完 effect 才隐藏，慢的时候（尤其 dev）能看见一整屏「开始页」。

现在的做法：

1. `layout.tsx` 里在 `<body>` 最前面塞了一段**同步脚本**：本次浏览吹过蒲公英
   （`sessionStorage["medai:intro"] === "1"`）就在解析阶段给 `<html>` 打上 `data-intro-seen="1"`。
2. `globals.css` 里 `html[data-intro-seen="1"] .boot { display: none !important; }` ——
   第一帧就不画开场，不是「先画出来再淡出」。
3. 草地淡入从 1.6s 收到 0.45s（回来时不必再从雾里浮一次）。
4. 气泡改说一句「回来啦」（`rabbitBack()`，5 句随机，不占欢迎语分类），
   而不是重新做一遍自我介绍。

实测：返回过程中采样 9~10 次，开场页出现 **0 次**。

## 七、语录库：四个分类

`src/data/rabbit-quotes.ts`，每类 10~12 句，直接往数组里加就行：

| 分类 | key | 语气 | 用在哪 |
| --- | --- | --- | --- |
| 欢迎语 | `welcome` | greet | **页面加载时**只从这一类随机抽一句（返回时不走这里，用 `BACK`） |
| 焦虑安抚 | `comfort` | care | 等结果、反复查症状、越查越怕 |
| 健康提醒 | `health` | remind | 喝水、早睡、久坐、按时吃药 |
| 就医提示 | `medical` | visit | 什么情况别在家等、该打 120 |

- **页面初始化**：`rabbitGreet()` → 只抽欢迎语。
- **点兔子**：`rabbitRandom()` → **四个分类一起抽**，欢迎语也会出现。
- 随机做了「最近四条不重复」，连点不会连着蹦同一句。
- 欢迎语刻意不写"早上好"这类时段词，什么时候加载都念得通。
- `lineFrom("comfort")` 可以指定分类抽一句（留给以后"换一句安抚"这类按钮）。

自检：`npx tsx scripts/quotes-test.ts`（16 项：分类规模、无重复、长度、600 次随机四类全覆盖）。

## 八、预留接口：showBubble

### 在 React 里

```ts
import { showBubble, rabbitSay, rabbitGreet, rabbitRandom, rabbitThinking } from "@/lib/rabbit-speech";

// 【主接口】用户提交问诊表单后，把大模型返回的整段回复直接丢进来：
// 自动压成一句（≤46 字，超长在逗号处断）+ 自动配一句鼓励话术
showBubble(replyText);

// 也可以自己指定鼓励语或显示时长
showBubble(replyText, { tail: "慢慢来，我在的", duration: 20000 });

// 说一句普通的话（不压缩、不配鼓励）
rabbitSay("我先看看你的化验单～", { tone: "care" });

// 其它
rabbitGreet();      // 欢迎语（只在 welcome 分类里抽）
rabbitRandom();     // 四类随机一句
rabbitThinking();   // 等模型时先占位，下一句来了自动替换
```

`tone` 只有 `care` 的鼓励行和边框会用一点点色相区分：`greet` / `care` / `remind` / `cheer` / `reply` / `warn`。
气泡上不显示任何"绒球医生"之类的标签，只有正文。

### 在控制台或非 React 代码里

页面加载后有一个全局的 `showBubble`，还有一个命名空间 `window.medaiRabbit`：

```js
// 最直接：表单那边不用记命名空间
showBubble("大模型的回答……");

// 等价写法
medaiRabbit.showBubble("…");
medaiRabbit.reply("…");     // 别名
medaiRabbit.say("…", { tone: "care" });
medaiRabbit.greet();
medaiRabbit.random();
```

### 已经接上的地方

- 页面加载完（蒲公英吹散后）→ 欢迎语
- 点兔子 / 点气泡 → 随机关心话术
- 打开一份档案 → 「我趴在这儿听你说，慢慢来。」
- 发消息 → 「我看看呀，稍等我一下…」（常驻）
- 收到回答 → 回答摘要 + 鼓励话术
- 请求失败 → 「刚刚没接上，再试一次好不好？我在的。」（warn）

完整的回答仍然留在左侧对话里，气泡只显示第一句 —— 它的作用是「兔子在跟你说话」，
不是替代阅读区。

## 十、边界

- 气泡只说关心、鼓励、提醒这类话，**不出现诊断结论**；诊断内容在对话里，带免责声明。
- 语录是本地写死的短句，不调模型、不联网，所以点兔子是零延迟的。
- 移动端问诊态气泡让位属于设计选择：那块屏幕没有不遮挡的位置。
  如果以后想让手机也有气泡，需要把问诊框改成可收起的半屏。
