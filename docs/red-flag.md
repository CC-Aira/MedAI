# 红旗症状拦截

有些话不该由 AI 顺着往下问。

用户说「胸口疼，喘不上气，出冷汗」，正确的回应不是「疼了多久？压着疼还是闷着疼？」，
而是「先别在这儿聊了，现在打 120」。这套判定放在 `src/lib/red-flags.ts`。

```
用户输入
   │
   ├─ detectRedFlags(text)   ← 纯正则，本地，0 网络
   │
   ├─ 命中 ──▶ saveRedFlagTurn() ──▶ 落库（flag = redflag.emergency）
   │              │                     │
   │              │                     └─▶ 红卡片 + 兔子改口
   │              └─▶ 不建上下文、不调模型、不查 AI 配置
   │
   └─ 没命中 ──▶ 照常走原来的问诊流程
```

## 一、为什么不交给模型

三条理由，一条比一条硬：

1. **要快**。实测走模型 1646ms，本地拦截 126ms。真出事的时候，十几倍的时间差就是「还在等它说话」。
2. **要稳**。模型有采样温度，同一句话两次回答可能不一样；这种话每次必须一模一样。
3. **要有底气**。没配 Key、额度用完、上游挂了，拦截照样得工作 —— 所以它被放在
   `requireOwnedConsultation` 之后、`buildChatContext` 之前，完全不碰 `isAiReady()`。

代价是只能认「直白的说法」，绕圈子的话会漏。这个取舍是刻意的：**宁可漏，不可误伤**。

## 二、规则长什么样

一共 11 条规则，按 `level` 分两档，另有一种卡片形态：

| id | level | 卡片头 | 认什么 |
| --- | --- | --- | --- |
| `chest` | emergency | 先别在这儿聊了 | 胸口疼 / 心前区痛 / 压榨样痛 |
| `breath` | emergency | 先别在这儿聊了 | 喘不上气 / 呼吸困难 / 憋气 |
| `conscious` | emergency | 先别在这儿聊了 | 意识不清 / 昏迷 / 晕倒晕厥 / 抽搐 / 叫不醒 |
| `stroke` | emergency | 先别在这儿聊了 | 口角歪斜 / 一侧肢体无力发麻 / 说话不清 |
| `bleeding` | emergency | 先别在这儿聊了 | 大出血 / 止不住 / 呕血吐血咯血 / 黑便柏油便 |
| `anaphylaxis` | emergency | 先别在这儿聊了 | 喉咙发紧发肿 / 嘴唇舌头脸肿 / 全身起疹、过敏性休克 |
| `self_harm` | emergency → `care` | 这句话我认真对待 | 不想活 / 自杀 / 轻生 / 想死（`疼得想死` 这类口头语放过） |
| `chest_tight` | urgent | 这个程度别拖 | 胸闷 / 胸口发紧 |
| `headache` | urgent | 这个程度别拖 | 剧烈头痛 / 炸裂样痛 / 痛得受不了 |
| `stool_blood` | urgent | 这个程度别拖 | 便血 / 大便带血 |
| `belly` | urgent | 这个程度别拖 | 肚子痛得打滚 / 直不起腰 |

`self_harm` 的 `level` 是 `emergency`（同样立刻中断问诊），但 `kind` 是 `care`，
卡片配色和话术完全不同 —— 不喊「去急诊」，而是「先给信得过的人打电话，全国心理援助热线 12356」。
隔着屏幕对一个想自杀的人说「请立即就医」，是把人推开。

## 三、最麻烦的部分：别把人误拦

中文里否定和假设太多，单纯匹配「胸痛」两个字会把「我没有胸痛」也拦下来。

判定顺序是：命中词 → 回看它前面 6 个字 → 命中下列任何一条就放过。

| 回看内容 | 例子 | 处理 |
| --- | --- | --- |
| `NEG_BEFORE`：没有 / 不 / 没 / 未 / 无 | 我**没有**胸痛 | 放过 |
| `HYP_BEFORE`：如果 / 要是 / 万一 / 假设 / 会不会 / 算不算 | **如果**胸痛该怎么办 | 放过 |
| `PAST_BEFORE`：以前 / 之前 / 曾经 | **以前**吐过一次血 | 降到 `urgent`（自伤类不降） |
| `unlessBefore`（逐条规则自带） | 胸痛**已经好了** | 放过 |

反过来，有两句是**明明在问也照样拦**的，写进测试固定住，免得以后有人当 bug 改掉：

- 「我有点**担心胸痛**」→ 拦。句子里已经有这两个字，宁可让人白跑一趟。
- 「有必要为**胸闷**去急诊吗」→ 拦。同上。

这是刻意的取舍：**误伤的成本是白跑一趟，漏掉的成本是别的东西。**

## 四、落库与刷新

回答不写进气泡，写进数据库，并且在 `Message.flag` 里存 `redflag.<kind>`：

| 存的值 | 前端画成 |
| --- | --- |
| `redflag.emergency` | 深红卡片，正文让人打 120 |
| `redflag.urgent` | 琥珀卡片，今天之内看一次 |
| `redflag.care` | 深棕卡片，先找人陪着 |

刷新之后照样是红卡片 —— 这一点很重要：如果 flag 不进库，第二天再看这段对话就变成
普通气泡了，那时它读起来就像"AI 顺着聊了两句"，完全看不出当时是拦下来的。

同时往 `Consultation.redFlag` 记一份 `{firstAt, count, ids, labels}`，就诊摘要要用它写
「这次问诊里出现过需要马上就医的信号」。

## 五、界面上的三处

1. **对话里的红卡片**：左侧有 `!` 圆点、右上角标「本地规则拦截」。标出来是为了让读的人
   知道这句不是模型说的 —— 它没有温度，也不该有。
2. **兔子的反应**：不念那段话（气泡放不下，也不该由一只兔子来说），改成
   「这个别在网上聊了，先去医院好不好？」+ `tone: "warn"`。
3. **输入框下面常驻一行**边界提示：胸痛、呼吸困难、意识不清、大出血这类情况别在这儿聊。
   常驻而不是弹窗 —— 弹窗会被点掉，常驻的才叫边界。

## 六、自检

`scripts/redflag-test.ts`（纯函数，40 项）+ `scripts/check-flow.mjs` 第 [1][2] 段（端到端），
覆盖：

- 11 条规则各自能命中
- 否定、假设、过去时不误拦
- 「担心胸痛」这类边界句照样拦（有注释说明这是取舍）
- 端到端：响应头 `x-medai-flag: redflag`、<1.5s、刷新后仍是红卡片
- 端到端：否定句走正常回答，不会被拦
