# 吊在草地上的木板（今天的药）

主页左上那片天上吊着一块木板，写的是**这个账号下所有档案今天**的用药进度。

```
listTodayBoard(ownerId)  ──▶  page.tsx（服务端算）
                                   │
                     ┌─────────────┴──────────────┐
                 桌面 │                            │ 手机
                     ▼                            ▼
            engine.setBoard()              .medtoday 一条
            3D 吊牌 + canvas 贴图           档案栏顶上的一行
                     │                            │
                     └────────► 点一下 ◄──────────┘
                                   │
                            .signcard 明细卡片
                          （每位一行，每颗药一行）
```

## 一、为什么是木牌，为什么不让兔子举

这个号能存全家的档案。**木牌回答的是「今天全家该吃什么」，兔子回答的是「你现在哪不舒服」** ——
两件事不该塞进同一个身体里。兔子一举牌子，就变成"它在催我吃药"，而你本来是想找它说话的。

挂在左上那片天上还有个好处：档案栏和兔子中间正好空着一块，牌子吊在那儿不挡人、不挡路，
链条一路拉出画面，像本来就挂在画外某颗钉子上 —— 而不是弹在屏幕上的一个控件。

## 二、什么时候出现

只有**真的设了用药跟踪**的档案才上榜，条件是三条同时成立：

| 条件 | 说明 |
| --- | --- |
| `isActive` | 停用的药不算 |
| `timeOfDay` 非空 | 没填几点吃，就没有"今天该吃几次"这回事 |
| `remainingDays !== 0` | 疗程走完的药，今天不该再吃 |

一个符合条件的都没有 → `entries` 为空 → **木牌照样立着**，只是板子上写
「今天还没有要吃的药」，下面两行小字说清楚怎么用：在档案里加一条在服的药、填上每天几点吃。

> 原先的设计是「一个都没有就缩回土里，不拿空牌子占地方」。
> 结果是自己都找不到这个功能了 —— 空地上一根木棍都没有，谁知道这儿本来有块牌子。
> 空板子本身就是入口：点一下会弹一张说明卡，写清楚这块板子是干什么的、怎么让它有内容。
> 这也解释了为什么 `setBoard()` 不再因为 `entries` 为空就 `return`。

排序也要紧的排前面：先按「已经过点还没吃」的次数降序，再按「今天还差几次」降序，
最后按姓名。这样每次刷新顺序都一样，不会自己跳来跳去。

## 三、桌面：吊在左上空的木板

`engine.js` 里 `woodMaps()` / `sawnBoard()` / `buildSign()` / `layoutSign()` / `signQuad()` / `updateSign()`。

- **位置**：按**屏幕像素**摆，不写死世界坐标。`layoutSign()` 量一下左侧档案栏（`.records`）的右边界，
  取「栏右边 + 34px」当板子左缘，垂直落在视口 23.5% 处，再反推它该站到离镜头多远的位置。
  好处是换窗口宽度时它一直在同一块天里，也不会被档案栏压住（问诊时栏会滑走，`right` 是负数，夹回 0）。
- **大小**：屏幕宽 252px（`SIGN_W_PX`），世界尺寸 1.52 × 0.70 —— 参考图那种长条锯切板，
  横向长、纵向窄。太小字就糊，太大就盖住兔子。
- **板子本体**：`ExtrudeGeometry(sawnBoard(...), depth 0.05)` + 2 段倒角。
  `sawnBoard()` 用 64 段折线上下一各走一点（±0.012 世界单位），边缘是锯齿口的，不是机加工那种笔直边。
- **链条**：`InstancedMesh(TorusGeometry(0.024, 0.0078))`，一节转 90° 交替，串起来正面看是环、
  侧面看是一条线，才有链子的层次；每侧约 150 节，长度 6.4 世界单位，一路拉出画面外。
  板子两头上沿各一个挂环，链条末端正好落在环里。
- **摆动**：`signSwing` 组的原点在链条顶端，`rotation.z / x` 各给一个极小的正弦 ——
  板子像真吊着在晃，而不是贴着一张图。幅度 0.005 rad，落在 6.75 个单位的力臂上也只有几像素。
- **木料**：`woodMaps()` 现场算 **1024 × 512 的四张图**（颜色 / 法线 / 粗糙度 / 端面），
  全部代码生成，仓库里没有一张木头图片。
  - 先算**高度场**（`Float32Array`），再对邻居做中心差分求导得法线图。
    用 `normalMap` 而不是 `bumpMap`：凹凸是算出来的方向，光怎么转都对；`bumpMap` 只是灰度近似。
    高度场边界做像素复制，否则四周会多出一圈假棱。
  - 年轮（山形纹）：`gd = v + 0.045·(u−0.45)²` 打一点拱，再叠三层**沿纹拉长**的值噪声
    （`u` 系数小、`v` 系数大），最后 `sin(gd·density·2π)`。频率放低会立刻变成等高线 —— 踩过。
  - 每圈年轮有自己的编号 `rId = floor(pos)`，用 `rId` 做哈希得 `h1/h2`：
    `thr` 由 `h1` 决定（线多粗）、`bandDark` 由 `h2` 决定（线多深）。
    **同一圈内部整条一致，不同圈之间随机** —— 粗细处处随机的线是贴图，一眼就露馅。
  - 晚材用 `smoothstep(thr, thr + 0.035, ring)` 硬切：过渡宽度固定得很窄，粗细全靠阈值高低。
    带宽了还给宽过渡，就会糊成一片阴影而不是一条线（踩过）。
  - 木头也会有「淡掉」的段落：`fade` 让线走着走着消失；`presence` 让整片区域糊掉。
  - 木节藏在右下角空地（避开文字），纹路绕着它弯；另有树脂线、导管孔、锯痕、四层纤维。
  - **端面单独一张材质**：`ExtrudeGeometry` 的侧壁认成第二组，贴年轮横切的弧线。
    分组要按 `geo.index ? idx[gk] : gk` 取顶点 —— 挤出是非索引几何，`index` 是 `null`，
    照 `idx[gk]` 取会错位甚至报错（踩过）。
  - 材质：板面 `MeshStandardMaterial({ map, normalMap, roughnessMap, color: 0xe4dcd0 })`，
    端面另一套。**哑光靠 roughnessMap 和法线，不靠画高光** —— 画上去的高光一转身就错位。
- **板子自己的斜射光**：主光（太阳）在板子背后，正面凹凸会被抹平。所以单独给木板加一盏
  `layers.set(2)` 的 `DirectionalLight`，木板 `layers.enable(2)`、相机也 `enable(2)` ——
  只照亮板子，草地上一点不受影响。光强调过头会过曝，0.46 刚好。
- **出场**：`signShown` 从 0 指数逼近 1，HTML 文字层跟着淡入。
- **命中**：`signAnchor()` 把木板的 8 个角投影到屏幕取包围盒，`hitSign()` 直接比矩形。
  比 raycast 便宜，也更宽容（不用精确点到板子上）。
- **明细卡片**：点牌子 → `.signcard` 从**板子下面**长出来（`top = anchor.bottom + 12`），
  小尖翻到卡片头上指着板子。牌子吊在天上，卡片往上会直接顶出画面。

### 换过窗口大小之后：别只重摆一次

`layoutSign()` 里板子的横向位置取自档案栏右边缘 `document.querySelector('.records').getBoundingClientRect().right`
（挂在那片天上），纵向靠相机反投影。**这两样在 resize 那一帧都还是旧的**：
`.records` 刚被媒体查询改过、还没重排完，相机也还在往新位置插值。
结果是从手机尺寸切回桌面时，木牌会停在左下方半空里，要等下一次 resize 才回原位 ——
卡片是按当时的 `signAnchor()` 摆的，也就跟着长歪，看起来像吊牌散了架。

现在 `resize()` 里除了摆一次，还记下 `signRelayout = 1.4`（秒）；`updateSign()` 每帧检查这个值，
没走完就再 `layoutSign()` 一次。一秒多之后 CSS 和相机都落定了，板子就停在正确的位置上。
`check-board.mjs` 里加了断言：切回桌面后锚点必须和切走前差 < 24 px。

### 板面上的字：为什么用 HTML，不画进贴图

第一版的字是画进 canvas 贴图的。换字体要重画、改一个字要重画、屏幕缩放后发虚，
而且**每次数据变都要重传一张 3D 贴图**。现在改成一层 HTML 贴在板面上：

```
signQuad()  ──▶  板面四角投影到屏幕（4 个 CSS 像素坐标）
              ──▶  quadTransform() 求单应矩阵（src/lib/css-quad.ts）
              ──▶  .medsign 每帧写一次 matrix3d
```

- `.medsign` 按「一块 262 × 107 的纸」排版，`transform-origin: 0 0`，`pointer-events: none`
  （点还是点给 3D 板子，走 `hitSign()`）。
- 板子是斜着立的，四角投到屏幕不是矩形 —— 按中心点摆 div 会差出一条边。
  单应矩阵让**四个角各自钉到板面四角**，文字跟着透视缩，看着才像贴在上面。
- 文字区比板面内缩一圈（`SIGN_TEXT_W/H = 1.42 × 0.58`），字不贴着锯口。
- 字号是按屏幕上板子约 252 px 宽定的：标题 10.5 px、行 12.5 px、大数字 24 px。
  再小就糊，再大就挤 —— 板子只有 116 px 高，一行都省不出来。
- 不要画 1px 横线做分隔：被 matrix3d 缩放后会半像素消失，中间断一段。靠留白分就够了。

> `window.__meadow` 只在开发和 `?debug=1` 下挂。生产环境跑截图 / 检查脚本要走
> `http://localhost:3100/?debug=1`，否则拿不到 `signAnchor()` 这类接口。

牌子挂在半空，草地上的蒲公英不会再挡到它 —— 原来那块「板子脚下别种蒲公英」的
`clearOfSign()` 判定跟着一起去掉了。

## 四、手机：换成档案栏顶上的一条

手机上（390×844）草地只在 110–240 px 这一条里露出来，下面全是档案栏。
木牌缩小到放得下就一个字也看不清，放大就压在兔子脸上 —— 所以**手机上不挂 3D 吊牌**
（`updateSign()` 里 `want = isMobile ? 0 : signTarget`），换成 `.medtoday` 一行：

```
● 今天的药  2/5  [2 次没吃]                          ›
```

圆点：绿=今天该吃的都吃了，红=有过点没吃的。点它弹同一张明细卡片。

`.medtoday` 在桌面是 `display:none`，不占位。

## 五、明细卡片

点吊牌（或手机那条）→ `.signcard`，每位档案一段，每颗药一行：
`时间 · 药名 · 已服/没吃/待吃`。

**每一行本身就是打卡按钮** —— 不用再点进档案页：

```
○ 11:03 二甲双胍片        没吃      ← 点整行
✓ 15:03 阿托伐他汀钙片    待吃      ← 再点一次撤销
```

- 左边一个空心圈，打卡后填实打勾。**整行是热区**，不用去瞄准那个小圈。
- 打卡 / 撤销直接调 `POST|DELETE /api/medications/:id/checkin`，成功后重新拉一份
  `GET /api/medications/board` —— 分子分母、过点标记、谁排前面全都变了，本地算容易漏。
- 三处同步：行内状态、表头 `2/5 → 3/5`、**3D 板面上的字**（`setBoard()` 走同一份数据）。
- **人名顺序在打开那一刻冻结**（`sheetOrder`）。板子本身按「谁还没吃」排序，打完卡会重排 ——
  不冻结的话，手指点下去那一行会在原地换人，没法连点。
- 打卡按钮 `aria-pressed`，键盘也能按 Tab 走过去敲。

定位：

- 桌面：挂在吊牌**正下方**（`top = 板子下缘 + 12`），头顶有个小尖指着板子。
- 手机：没有木牌可依，从 `top: 176px` 弹出来（让开兔子头上那个气泡）。
- **开完再量一次高度**：行变成按钮后每行变高，900 高的屏幕上卡片底部会跑到 923。
  现在 `useEffect` 里量 `getBoundingClientRect().bottom`，超出就整体上提，回到视口内。
- `z-index: 37` —— 要盖过兔子的气泡（36），但别盖住顶栏（40）。
- 点草地别处就收起。

## 六、顺带修的：连续漏服的计数

`computeSchedule()` 里 `missedStreak` 原来往回数 **30 天**，于是一条两个月前建档、
从来没打过卡的药会显示「连续漏服 24 次」——数字吓人，而且没有指导意义
（一周以前的漏服已经改不了了）。

现在是 `MISS_LOOKBACK_DAYS = 7`：

| 情况 | 结果 |
| --- | --- |
| 今天刚加的药，没打卡 | 0（锚点是创建日，走不到循环） |
| 3 天前开始，一直没打卡 | 3 |
| 60 天前的老药，从没打卡 | 7（封顶，不再报 59） |
| 有打卡记录 | 从最近一次打卡往回数，最多 7 |

界面上的「连续 N 次没打卡」和提醒里的关怀句都跟着这个数走。

## 七、自检

```bash
npx tsx scripts/schedule-test.ts        # 纯函数：漏服计数、疗程边界（11 项）
node scripts/check-board.mjs            # 造数据 + 截图：吊牌 / 手机条 / 明细卡片 / 卡片上直接打卡（33 项）
node scripts/shot-sign.mjs              # 单拍吊牌：整屏 + 特写（临时加 3 条药，跑完删）
node scripts/check-reminder.mjs         # 提醒文案回归（20 项）
```

`check-board.mjs` 会自己造 5 条药（含打卡和过点），跑完删掉。
截图落在 `docs/preview-signboard*.png`。

空板子的样子单独截过：

```bash
node scripts/shot-timeline.mjs          # 顺带截 docs/preview-signboard-empty*.png
```

它会把演示账号的药临时全停用 → 截图 → 还原（脚本 finally 里兜底，中途报错也会还原）。
