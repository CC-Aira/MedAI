# 病程时间轴

档案页的第五个 tab。把**建档 / 用药 / 问诊 / 结论**四类记录摞到同一条纵轴上，
一条线往下读就是这段病程。

## 为什么要做这张图

档案页原本是四个互不相干的 tab：用药在用药页、问诊在日历里、结论在另一个 tab。
想回答「什么时候开始吃的这个药、吃到第几天去复诊、复诊完加了什么药」，
得来回切三次、还得自己在脑子里对时间。时间轴就是把这一步省掉。

另外它是**给眼睛看的、不是给手点的**：答辩 PPT 里放一张病程时间轴，
比放四张截图更能说明「这个系统真的在记录一个人的病程」。

## 数据从哪来

不新建表、不写迁移、不加接口 —— 输入就是档案页手上已经有的四份数据：

| 来源 | 事件 | 用哪个时间 |
| --- | --- | --- |
| `Patient.createdAt` | 建立档案（带主诉 / 性别年龄 / 是否登记过敏史） | 建档时刻 |
| `Medication.startDate ?? createdAt` | 开始服用某药（剂量、频率、时间点、疗程） | **startDate 优先** |
| `Consultation.lastMessageAt ?? createdAt` | 一次问诊（有小结用小结，否则用最后一句） | **lastMessageAt** |
| `Note.createdAt` | 一条结论（星标排前面） | 创建时刻 |

**为什么不用 `updatedAt`**：归档、生成小结、点「这次聊完了」都会刷新 `updatedAt`，
拿它归日会让一次上周的问诊跳到今天。这条规则和问诊日历是同一套（见 `docs/visit-calendar.md`），
两个视图对同一件事必须落在同一天。

**为什么用 `startDate`**：医生说的是「从今天开始吃」，而这条记录可能是事后补录的，
建档时间比真正开始吃药晚几天 —— 时间轴上错这几天，整个病程的因果就读反了。

## 排序与分组

- **新的在上面**：打开就看见「最近怎么了」，往下翻才是旧病程；
- 同一时刻的排序：问诊 → 结论 → 用药 → 建档（临床上是「先看诊、再下结论、再开药」）；
- **按月分组**，组标题右侧写这个月有几条；
- 同一天的第二条起，日期列留空、只写时间，轴才不啰嗦。

## 四类记录的配色

| 类型 | 颜色 | 理由 |
| --- | --- | --- |
| 问诊 | 橙（`--accent`） | 病程里的「事件」，最该被看见 |
| 用药 | 绿（`--sage`） | 和治疗、在服状态同一套绿 |
| 结论 | 蓝灰 | 像是写在纸边的批注，不该抢问诊的注意力 |
| 建档 | 灰 | 起始点，安静一点 |

- 用 `createPortal` 挂到 `document.body`：档案页的 `.detail` 有入场动画，
  动画期间元素会成为 `position: fixed` 的包含块，挂在里面会跟着卡片跑到视口外（踩过这个坑）；
- 打开时锁 `body` 滚动，Esc 或点「关闭」退出；
- 投影视图里**不放「看原文」按钮**，截图干净；
- `@media print` 已经处理：Ctrl+P 直接存 PDF 时没有半透明遮罩，只有那张纸。

## 已知取舍

- **不显示单次打卡**。一天三次药、坚持一个月就是 90 个点，轴会被打卡淹没，
  真正想看的用药变化反而看不见。打卡进度看草地上的木牌和用药页。
- **停用时间没有单独事件**。`Medication` 没有 `stoppedAt` 字段，只有 `isActive` 布尔，
  所以在时间轴上只能把已停用的药标成「已停用」，说不出是哪天停的。
  要精确到那天得加字段 + 迁移，当前不值得 —— 停药日期在用药备注里能看到。
- **聊天原文过了保留期就没有了**。超 30 天的问诊在轴上还在（靠小结/标题），
  点「看原文」会读到小结或一句「原文已按保留策略清理」，不假装还在。
