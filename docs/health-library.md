# 疾病科普库 / 药品说明查询

主页左栏顶部的三个入口：**档案 · 疾病科普 · 药品说明**。后两个是这一版新增的独立页面。

## 页面

| 路由 | 内容 |
| --- | --- |
| `/library` | 按科室浏览 + 关键词搜索，**90 条**常见病与多发病，13 个科室全覆盖 |
| `/library/[slug]` | 单病种八节：为什么会得 / 有什么表现 / 这些情况别拖 / **去医院一般会做哪些检查** / 怎么预防 / 治疗原则 / 日常怎么照护 / **流传很广，但不对** + 来源与更新日期 |
| `/drugs` | 按大类浏览 + 名称/商品名/成分/适应症搜索，**73 种**常用药，10 个药理大类 |
| `/drugs/[slug]` | 单药六项：适应症、用法用量、禁忌人群、副作用、药物相互作用、特殊人群注意事项 + **起效 / 漏服 / 储存**三卡 + 来源与更新日期 |

未登录访问会 307 回 `/login`（所有页面都过 `requireUser()`）。

## 数据

```
src/data/
├─ knowledge-types.ts   # Disease / Drug / Index 的类型
├─ departments.ts       # 13 个科室及各自「看什么」
├─ diseases.ts          # 汇总 + 按 slug 取 + 统计
├─ diseases/*.ts        # 按科室分文件，14 个文件，每文件 2～10 条
├─ drugs.ts             # 汇总 + 十大类映射 + 统计
└─ drugs/*.ts           # 按药理分类分文件
```

新增一条疾病：在对应科室文件的数组里加一个对象，`slug` 唯一即可，列表和搜索会自动收录。
新增一种药：同理，另外要在 `src/data/drugs.ts` 的 `GROUP_OF` 里给它指定一个筛选大类，
否则会落到「其他」。**新增 slug 忘了配 `GROUP_OF` 会在列表里显示成「其他」而不报错**，
改完用 `scripts/knowledge-test.ts` 跑一遍能抓到。

两个库都**不是**数据库表：内容随代码走，`git diff` 可审，不需要迁移。

### 内容字段

`Disease` 除了六节正文，还有两份是「普通人最需要、但书上不常讲清楚」的：

- `checks` —— 去医院一般会做哪些检查。3 条左右，按必要性排序，第一条通常是能在门诊当场完成的。
- `myths` —— 流传很广但不对的说法。**格式固定为「「说法」——为什么不对」**，
  先说人话再说理，不训人。

`Drug` 三卡：

| 字段 | 回答的问题 |
| --- | --- |
| `onset` | 多久起效？什么时候该觉得好转？ |
| `missedDose` | 漏了一次怎么办？补不补、加不加倍？ |
| `storage` | 怎么放？开封后多久用完？ |

这三项是最常被问到、又最容易在说明书里藏起来的东西，所以单独拎出来做成卡片，
而不是塞进「用法用量」一大段里。

## 配图

列表卡、疾病详情头、药品详情头各有一张插图：`src/components/DeptArt.tsx`。

- **自绘 SVG 线稿，不是照片也不是位图**：18 个分类各一组 64 × 64 白色线稿，
  垫一个低饱和渐变圆底（`TONE` 表按分类给 `from/to`）。矢量、缩放不糊、换主题只改一个色值，
  也没有任何图片版权问题。
- 疾病按 `department` 取图，药品按 `GROUP_OF[slug]` 取图，两者共用同一个组件。
- 未命中的 id 一律回落 `other`，**新增科室不会出现空白**。
- 用法：`<DeptArt id={d.department} size={38} />`，`size` 决定边长，描边宽度是相对的。

## 检索

`src/lib/knowledge-search.ts`，纯函数，跑在客户端（数据只有几十条，输入即时出结果）：

1. `normalize()`：NFKC 全角转半角 → 去空白和标点 → 小写 → **同义词归一**
   （发烧→发热、拉肚子→腹泻、睡不着→失眠、痘痘→痤疮、脚气→足癣、血压高→高血压……）
2. `splitTerms()`：按空白和标点切词，多词之间是 **AND** 语义
3. `matchScore()`：按字段权重打分，字段内多值（别名、关键词数组）**逐段**比较
   - 命中优先级：完全相同 > 前缀 > 包含 > 反向包含（「高血压吃什么药」能捞出「高血压」）
   - 疾病权重：名称 100 / 别名 60 / 关键词 40 / 摘要 16 / 症状 14
   - 药品权重：通用名 100 / 商品名 70 / 成分 45 / 适应症 34 / 分类 28 / 关键词 26
4. `excerpt()`：把命中的关键词附近截成摘要（内部维护「扁平下标 → 原文下标」映射，因为归一化会删标点）

## 内容口径

- 面向普通人，讲清「是什么、为什么、怎么办」，不写具体处方。
- 药品**剂量只写常见成人范围**，并明确「以药盒说明书和医嘱为准」；儿童、孕妇、肝肾功能不全者的剂量一律交给医生。
- 每条都有 `source`（指南 / 药典 / 说明书范本）和 `updatedAt`（整理校对月份），列表和详情都展示。
- 详情页底部固定免责声明：科普不能替代面诊。

## 自检

```bash
# 数据完整性 + 检索召回（90 条疾病 / 73 种药）
npx tsx scripts/knowledge-test.ts

# 页面端到端（需先启动 3100）
node scripts/knowledge-page-test.mjs http://127.0.0.1:3100

# 截图（无头 Chrome + CDP，产物在 docs/preview-kb-*.png）
node scripts/shot-kb.mjs http://127.0.0.1:3100
```

`knowledge-test.ts` 覆盖：slug 唯一、六项字段非空、日期格式、10 组疾病查询、10 组药品查询、空查询与纯标点。

`shot-kb.mjs` 拍的是：列表（并统计插画张数）、疾病详情（并核对八个小节标题是否齐全）、
误区特写、药品详情（并确认「起效 / 漏服 / 储存」三卡存在）、起效卡特写、
四个新科室条目能否打开、手机宽度（390px）下列表不挤。

## 构建注意

构建时把两个环境变量置空即可绕开（不影响删除语义以外的行为）：

```bash
CODEBUDDY_TOOL_CALL_ID="" CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR="" npm run build
```
